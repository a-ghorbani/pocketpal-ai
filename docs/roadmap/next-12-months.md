
**核心判断**: 下一阶段分两条并行线——
1. **发布线**: 将已实现功能分批发布，让 v1.15.2 用户逐步获得新能力
2. **创新线**: 在本地推理基础上，增加多模态、自主Agent、分布式推理等下一代能力

**目标版本**: v1.16.0（E2EE备份）+ v1.17.0（Auth登录）

| 工作项 | 说明 | 架构影响 |
|--------|------|----------|

**ADR-001**: 采用分批发布策略（v1.16 → v1.17 → v1.18），而非一次性发布所有功能。
**Trade-off**: (+) 降低单次发布风险，用户逐步适应 (-) 开发团队需维护多个功能开关（Feature Flags）。

## 📝 原则与假设

1. **发布优先**: 已实现的功能优先发布，不让代码在main分支"腐烂"
2. **设备分级**: 始终按设备能力动态调整功能，不打压低端用户
3. **隐私第一**: 所有新功能默认本地执行，云端仅作为可选增强
4. **开源生态**: 插件系统、Pal Manifest、MCP工具接口全部开放文档
5. **路线图是假设，不是承诺**: 每月末根据用户提供反馈和商店评论调整下月优先级
