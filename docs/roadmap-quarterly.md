## 📅 第一阶段：基础设施夯实期 (2026.07 — 2026.09)

### 主题：补短板，为规模化打地基

#### 🎯 1.1 用户账号与云同步系统

这是**最紧迫的架构投资**——没有账号系统，所有功能都是"单设备孤岛"。

**架构决策 (ADR-2026-001):**

```markdown
# ADR-2026-001: 引入轻量用户账号 + 端到端加密云同步

## Context
目前所有聊天/Pal/配置数据仅存储在本地 AsyncStorage，用户换机即丢失。PalsHub IAP 也受限于无账户系统。

## Options Considered
- A) 自建后端 (Flexible 但运维成本高)
- B) 接入第三方身份 (Google/Apple) + IPFS/对象存储
- C) 去中心化 P2P 同步 (过于复杂，不适合当前阶段)

## Decision
采用 **Option B**: Firebase Auth (Google/Apple 登录) + S3 兼容对象存储。  
- 聊天记录端到端加密 (E2EE)，服务端不可读
- 配置/Pals/TTS 偏好等开放存储
- IAP receipt 通过账号维续，跨设备恢复

## Consequences
(+) 用户数据跨设备可用，留存率提升  
(+) IAP 可跨设备恢复，支付转化率提升  
(–) 引入后端依赖，需维护服务器端组件  
(–) 首次同步需处理冲突策略（LWW + 分片）
```

**关键交付**: 账号注册/登录 → 聊天同步 → Pal 同步 → IAP 恢复

#### 🎯 1.3 模型管理重构

**问题**: 当前模型下载/管理散落在 UI 层，无法批量管理、无法后台下载、无法感知存储空间。

**目标**: 引入 `ModelManager` 模块，统一管理：
- 模型下载队列 + 断点续传
- 存储空间感知 (基于已有的 `getAvailableMemory()` API)
- 模型版本管理 / 自动更新提示
- 模型分类 (对话基座 / 推理增强 / TTS / VLM)

## 📅 第二阶段：语音与人机交互升级 (2026.10 — 2026.12)

### 主题：让对话真正"自然"

#### 🎯 2.1 语音输入 (STT) + 语音对话模式

**架构决策 (ADR-2026-003):**

```markdown
# ADR-2026-003: STT 引擎选择 — 本地 vs 云端

## Options
- A) 本地 Whisper.cpp (通过 llama.rn 复用推理后端)
- B) 云端 STT (Google/Apple Speech API)
- C) 混合策略: 本地 Whisper 默认 + 云端 Fallback

## Decision
Option C: Hybrid STT
- 首选本地 Whisper.cpp 推理 (离线可用，隐私优先)
- 语言不支持或质量不足时 Fallback 到系统 Speech API
- 架构上新增 `SpeechEngine` 接口层
```

**关键交付**: 
- 语音输入按钮 → Whisper 识别 → 填入消息框/直接发送
- 全语音对话模式 (自动 STT → LLM → TTS 闭环)
- 语音引导设置流程 (升级 v1.16.0 的 6-step 引导)

## 📅 第三阶段：智能与知识增强 (2027.01 — 2027.03)

### 主题：从"对话"到"智能助手"

#### 🎯 3.1 知识库 / RAG 系统

**架构决策 (ADR-2026-005):**

```markdown
# ADR-2026-005: 移动端 RAG 架构

## Context
用户希望 AI 能"记住"文档、笔记、网页内容，基于私有知识回答问题。

## Decision
- 文档解析: 本地提取 Text + 分块 (Chunking)
- Embedding: 使用本地 Nomic Embed Text / BGE 模型 (GGUF 格式)
- 向量存储: SQLite + FTS5 混合搜索 (BM25 + 语义)
- 检索: 混合检索 (语义 + 关键词) → Re-ranking → LLM 回答
- 全部在设备端完成，无需云端

## Trade-off
(+) 完全离线，隐私安全  
(–) 大型文档集 (~100MB+) 需做分段索引，首次索引时间较长  
(–) 手机端 Embedding 速度受限于设备算力
```

**关键交付**:
- 文档导入 (PDF/TXT/Markdown/网页剪藏)
- 知识库管理 (多库切换、标签、搜索)
- 对话中 @知识库 引用
- 自动索引后台服务

---

#### 🎯 3.2 对话记忆系统升级

当前对话记忆是简单的滑动窗口。升级方向：

- **短期记忆**: 当前会话上下文 (已有)
- **工作记忆**: 同一对话中跨 session 的关键信息提取和持久化
- **长期记忆**: 跨对话的用户偏好、事实、关系的持久化记忆图谱

**架构决策**: 
- 引入 `Memory Graph` 模块，每个 session 结束时提取关键事实，存入本地图谱
- 使用轻量级本地 NLP 做实体/关系提取

---

#### 🎯 3.3 远程推理服务优化

- **多 Provider 支持**: Anthropic、Gemini、Groq 等服务商
- **自动路由**: 根据任务类型、模型能力、延迟自动选择最优 Provider
- **用量统计 & 配额管理**

## 📅 第四阶段：生态与平台扩展 (2027.04 — 2027.06)

### 主题：从 App 到平台

#### 🎯 4.1 插件 / 扩展系统

**架构决策 (ADR-2026-006):**

```markdown
# ADR-2026-006: 插件系统架构

## Decision
- 插件形式: 每个插件是一个独立的 JS Bundle + 声明文件 (manifest.json)
- 沙箱: Hermes 引擎沙箱执行插件代码，限制对原生 API 的访问
- 插件能力:
  - UI 扩展: 自定义面板、消息渲染器、快捷指令
  - 数据源: 自定义知识源、搜索后端
  - 工具: 自定义 MCP Tool
- 插件的生命周期管理: 安装 → 启用/禁用 → 更新 → 卸载
- 插件市场：内嵌在 PalsHub 中
```

---

#### 🎯 4.2 桌面端 / 跨平台扩展

- **macOS/iPad 原生适配**（已有部分 iPad 支持，进一步优化）
- **Windows/Linux 桌面版考虑**: 技术栈复用 (RN for Desktop / Tauri 跨平台)
- **架构决策**: 保持核心逻辑共享 (monorepo 结构)，仅 UI 层按平台适配

#### 🎯 4.3 多模型协作 (MoE)

- **模型流水线**: 一个任务可由多个模型协作完成
- 例: 小模型快速过滤 → 大模型深度分析 → 专用模型生成输出
- 例: STT (Whisper) → 指令路由 (小模型) → 推理 (大模型) → TTS (Supertonic)

#### 🎯 4.4 企业级功能 (可选)

- **本地 API 服务器**: 在手机上启动 HTTP 服务，供局域网内其他设备调用
- **LDAP/OIDC 企业认证** (面向企业部署场景)
- **审计日志** (用于合规场景)

## ⚠️ 风险与缓解

| 风险 | 可能性 | 影响 | 缓解策略 |
|------|--------|------|----------|
| 后端运维成本过高 | 🟡 中 | 项目可持续性 | 优先 Serverless，预留自建过渡路径 |
| 移动端 RAG 性能不足 | 🟡 中 | 用户体验 | 小文档优先，大文档提供桌面端备用方案 |
| 插件系统安全漏洞 | 🔴 高 | 用户数据泄露 | 严格 Hermes 沙箱 + 权限声明 + 人工审核 |
| 跨平台开发资源不足 | 🟡 中 | 交付延迟 | 先优化 macOS/iPad，Desktop 后置 |
| 创作者平台内容质量 | 🟡 中 | 品牌影响 | 审核机制 + 社区评分 + 举报系统 |
